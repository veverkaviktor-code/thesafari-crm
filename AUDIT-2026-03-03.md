### 4.2 Co je dobre

- **VARCHAR + CHECK** misto ENUM — konzistentni a spravne pro PostgreSQL
- **JSONB** pro adresy, tagy, settings — vhodne pro single-admin CRM
- **Parcialni index** na overdue fakturach — dobry napad
- **Composite indexy** na casto filtrovanych kombinacich
- **CHECK constraints** na cenach (>= 0) a datech (due_date >= issue_date)
- **Invoice auto-numbering** s `lockForUpdate()` — spravne reseni race condition
- **Spatie Activity Log** na klicovych modelech

### 4.3 Problemy

#### Kriticke
| Problem | Soubor | Popis |
|---------|--------|-------|
| `bank_transaction_id` bez FK | `create_invoices_table.php:27` | unsignedBigInteger bez constrained() — zadna referencni integrita |
| `users.role` bez CHECK | `add_role_settings_avatar_to_users.php:12` | Role muze byt libovolny string |

#### Stredni
| Problem | Popis |
|---------|-------|
| CASCADE vs Soft Delete konflikt | time_entries + order_costs maji cascadeOnDelete, ale orders ma SoftDeletes — forceDelete smaze data natvrdo |
| Chybejici SoftDeletes | subscriptions, tickets, time_entries — smazanim se ztrati historie |
| Chybejici relace v User modelu | Zadne hasMany definovane, prestoze FK existuji |
| BankTransaction izolovany | Zadna relace Invoice <-> BankTransaction na urovni modelu |
| activity_log bez timezone | timestamps() misto timestampsTz() — nekonzistentni |

#### Chybejici indexy
| Tabulka | Chybejici index | Duvod |
|---------|----------------|-------|
| customers | `name` (trgm GIN) | ILIKE vyhledavani v scopeSearch |
| customers, orders, invoices | `deleted_at` | Kazdy dotaz filtruje na deleted_at IS NULL |
| invoices | `paid_at` | Dashboard revenue queries |
| invoices | `bank_transaction_id` | Parovani s transakcemi |
| subscriptions | `(status, expires_at)` | expiringSoon() scope |
| activity_log | `created_at` | Dashboard latest() |

## 5. Bezpecnostni Audit

### 5.1 Kriticke

| # | Problem | Detail |
|---|---------|--------|
| 1 | **Zadna autorizace** | `authorize()` v Request trídach vraci `true`, role sloupec se nikde nepouziva |
| 2 | **Login bez rate limitingu** | Brute-force mozny, zadny `throttle` middleware |
| 3 | **API bez throttle** | `/api/tickets` endpoint (n8n) bez rate limitingu |
| 4 | **Attachment MIME validace** | `getClientMimeType()` je nespolehlivy — klient muze podvrhnout |

### 5.2 Stredni

| # | Problem | Detail |
|---|---------|--------|
| 5 | **Mail bez error handlingu** | `Mail::raw()` synchronne, SMTP timeout = 500 pro uzivatele |
| 6 | **Invoice total z klienta** | Server neoveruje `quantity * unit_price == total_price` |
| 7 | **CompanySetting::get() null** | Muze vratit neulozenou instanci — SPD QR kod bez IBAN |

### 5.3 Co je v poradku

- **SQL injection** — nehrozí (Eloquent parametrizovane dotazy)
- **CSRF** — aktivni pres Laravel session middleware
- **XSS** — Inertia/React renderuje data bezpecne
- **Mass assignment** — vsechny modely maji explicitni `$fillable`
- **Prilohy** — ulozeny na `local` disk (nepristupny pres web), download pres controller
